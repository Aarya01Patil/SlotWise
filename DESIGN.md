# SlotWise — design note

**Choice and scope.** One appointment, a synthetic clinic, and a small browser app: FastAPI, Pydantic, SQLite, plain JavaScript, and official Groq/Gemini SDKs. The LLM proposes tools; code owns patient identity, offers, exact appointment summary, consent, attempts, and receipts. Corrections revoke consent. Transactions, unique ownership, and patient-scoped idempotency protect bookings; uncertain commits trigger reconciliation. Unsupported requests and urgency stop scheduling or clarify. Handoff is explicitly simulated.

**Guardrails.** Local normalized checks reject common coding, harmful, injection, and cross-patient requests. Other text passes an isolated scope classifier; exact scheduling fragments avoid semantic false positives. Missing preferences are collected before search; search arguments must equal collected constraints. Only fixed reply tokens and validated clinic data reach patients, so arbitrary model prose is never displayed. This trades linguistic flexibility for a narrow, reviewable output boundary. Urgency detection and classification remain fallible, not clinical triage.

**Evidence.** Twelve development cases plus three withheld variants use reactive patient scripts, fresh databases, fixed clock and faults. Scores weight outcome 40, safety 35, state truth 20, efficiency 5; critical safety failure scores zero. Checks inspect transcripts, tool arguments/results, consent ordering, and SQLite rows. Transcript-only grading cannot prove a commit; database checks cannot establish empathy or clinical suitability. A small synthetic suite is not statistical evidence of general safety.

**Improvement.** Baseline safely hands off on a slot conflict even when matching alternatives remain. Development failure evidence generates a structured patch with prior value, proposed value, evidence references, and expected effect: `handoff → refresh_and_reconfirm`. Candidate recovery preserves constraints and requires fresh selection and consent. Repair can edit only this policy setting; unknown failures produce no patch. Promotion requires improved aggregate score, fixed target, no safety violation, and every previously passing assertion still passing across the unchanged suite. Rejected candidates preserve the active policy. This is bounded policy adaptation, not model training.

**Measured result.** Offline: 94.67 → 100, 26/30 → 30/30 passes, zero regressions (two repetitions). Live Groq booking is verified; the scored live loop is currently running and its final result will be recorded separately. An initial live run exposed guessed missing preferences; its evidence is preserved and a runtime guard was added before rerunning. This manual code repair is distinct from the automatic conflict-policy patch. Gemini exhausted its daily quota. Render's free SQLite storage is ephemeral; this is a synthetic demo only, in Asia/Kolkata.

**Production change.** Replace synthetic identity with clinic-verified authentication and server-side patient authorization before accepting real records.

**AI and judgment.** AI helped with architecture, implementation, tests, debugging, and documentation. Recorded human direction required scheduling-only guardrails, reported the valid “general” refusal, selected Groq after Gemini quota trouble, and chose Render. Human testing overrode the initial scope behavior; no independent manual authorship or unrecorded overrides are claimed. Candidate-reported time: about 6 hours.
